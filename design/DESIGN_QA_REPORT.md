## 结论与范围

完成四轮截图审阅和修改，覆盖时报八版、日报档案、信息源、设置与管理页。当前发现的前端 P0/P1 问题已关闭；最终检查未发现未处理的明显布局、导航或核心交互阻塞。品质参照 Awwwards / Webby / FWA，但不宣称获奖、完美或外部认证。

采用「晨刊 · 墨绿纸白」：刊物排版、清晰来源和行动说明、始终可见的移动导航、克制的交互反馈。两个候选方向和选择理由见 [设计系统](DESIGN_SYSTEM.md)。保留原生静态架构与真实数据。

## 四轮审阅记录

截图分别保存在 `artifacts/design/round-1/` 至 `round-4/`。每轮含四种尺寸的首页、档案、来源、设置和管理页，以及八版桌面截图。以下记录实际发现与修复，不以主观分数代替证据。

| 轮次 | 关键发现 | 修改与复核 |
|---|---|---|
| 1 | 手机导航缺失；9–11px 元信息太小；八版标签占四行；后台与阅读页风格割裂；分版最多展示七条 | 重建共享字体/颜色/间距；保留四入口；标签改为可横滑和方向键访问；统一管理页；完整展示条目。首版截图仍暴露刊头过高，继续修改 |
| 2 | 手机运行指标抢占首屏；重复栏目标题压低正文；长摘要阅读成本高；日期请求可能相互覆盖 | 手机折叠指标；压缩刊头和重复层级；原生展开保留摘要全文；增加请求顺序保护。手机首条标题位置改善到约 600px，但仍可收紧 |
| 3 | 总览标题重复；平板刊头堆叠过高；320px 管理标题断成孤字；部分表单边界对比偏弱；相同日报被重复请求 | 总览 h2 保留语义但视觉隐藏；压缩平板布局；平衡标题断行；表单边界改为 #818e7c；共享进行中的 JSON 请求。复核首页标题位置、axe 与请求数量 |
| 4 | 目录失败时日期文案及标签提示易误解；来源失败后筛选仍可操作；刷新可打断来源焦点；历史头条异常长；高密度标签及保存失败状态需实测 | 明确失败文案并隐藏无效提示；来源失败禁用筛选；相同健康记录不重绘；长标题字号 21–28px、来源提前且全文保留；完成故障、40 标签、长英文、管理保存失败/恢复检查 |

第四轮历史截图曾捕捉到日期切换的加载中状态，已修正截图脚本，等待真实标题及目标日期出现后重新截图。最早的内嵌浏览器裁切图片未用作视口验收；正式 PNG 来自独立 Chrome 实例。测试过程中发现的键盘顺序断言和响应夹具回调问题也已修正后重跑。

## 八项设计自检

| 维度 | 最终检查与依据 |
|---|---|
| 排版 | 中文正文 16px；元信息最低 12px；英文衬线刊头与中文内容层级分明；长标题不截断。四视口首页测量中小于 12px 的可见目标文本节点为 0 |
| 留白 | 1280px 最大容器、24/16px 外边距、细线分栏；压缩头部重复空间，保留文章段落呼吸感。见四视口前后对照 |
| 视觉层级 | 刊头 → 日期/版签 → 重点文章 → 来源 → 摘要 → 相关性/下一步。手机指标默认折叠，实际重点标题进入首屏 |
| 色彩 | 纸白、墨绿、少量赭色；状态不只依赖颜色。正文对比 14.33:1，次级文字最低已测 4.89:1；输入边界 3.41:1 |
| 动效 | 160–180ms 颜色/边界反馈，无循环动效或滚动劫持；减少动态效果模式已在浏览器中检查 |
| 微交互 | tabs 键盘、清晰焦点、展开全文、日期竞态保护、重试、未保存/撤销/保存失败保留修改、断开清理凭证，均有实测 |
| 响应式 | 1440、768、390、320 四组正式截图；追加 1920 功能检查；导航可见，主要导航与版签目标 >=44px，无页面横向溢出 |
| 原创性 | 从 OR MORNING 刊头延伸编号版签、报刊分栏与来源索引；使用现有真实内容与定制 CSS，没有套用外部站点布局或虚构视觉素材 |

## 实际功能验收

后端既有测试：`pytest -q` **24 passed，0.68s**。三个 JS 文件通过 `node --check`；`git diff --check` 无空白错误。

浏览器完整验收由 `scripts/check_design.py` 执行，最终结果见 [results.json](artifacts/design/qa/results.json)：**26 项 PASS**。

1. 初始化真实 manifest、61 个日期、真实 36/1/22/36 指标，未配置 Registry 时无假管理入口。
2. 八个版面逐一核对真实 payload；总览索引切版；方向键、Home、End、Tab 和清晰焦点。
3. 时报与档案独立切日期；延迟旧响应不覆盖新日期；真实原文链接打开新标签页。
4. MD、TEX 下载字节与仓库文件一致；无 PDF 的日期不显示假 PDF 入口。
5. 来源分组、选中状态与真实健康记录；五尺寸导航/版签/触摸尺寸/溢出检查。
6. 通过浏览器虚拟时钟触发实际五分钟轮询代码，检查展开内容、来源焦点、失败恢复与历史选择保留。
7. 隔离响应夹具覆盖目录/报告/来源错误与重试、空目录、零条目、长英文和中文摘要、高密度标签。
8. 管理页真实未配置状态；本地 Registry 夹具覆盖连接失败/恢复、编辑、撤销、保存失败/恢复、断开连接和内存凭证。所有请求截获在本地测试端点，没有调用生产 Registry。

另以真实 2026-10-17 日报的 153 字符标题检查四种尺寸：全文一致、来源在标题前、字号 <=28px、无横向溢出，见 [long-title-qa.json](artifacts/design/qa/long-title-qa.json)。真实数据页面没有浏览器控制台错误。

## 可访问性

axe-core 4.14.0 扫描桌面首页、320px 首页、未连接管理页、已配置本地夹具管理页：四处均为 **0 violations**。检查通过项分别为 28、29、21、23。

自动扫描的 `incomplete` 包括装饰箭头及横滑容器外的标签，不能直接算作通过。已人工查看标签/箭头并按实际颜色计算对比度：选中编号 6.96:1、普通次级文字 >=4.89:1；箭头非唯一操作提示。详细值见 [contrast.json](artifacts/design/qa/contrast.json)。

另在内嵌浏览器实际操作方向键、Home、End、Tab，确认标签焦点、阅读说明 summary 和正文 panel 的顺序及 3px 焦点线，见 [手动键盘记录](artifacts/design/qa/manual-keyboard.md)。测试脚本也复现此序列。减少动态效果媒体查询下无平滑滚动或过渡。

以上是针对已覆盖页面的检查，未进行完整屏幕阅读器或全部浏览器组合验收，不作 WCAG 认证声明。

最终本地 Chrome 测量位于 `results.json` 的 `lab` 字段；使用 PerformanceObserver 记录 LCP、CLS 和 Event Timing。实验环境为 Windows、本机 HTTP、独立无头 Chrome、未限速。测量数值随机器负载变化。

| 本次实验室观察 | 结果 |
|---|---:|
| LCP | 332ms |
| CLS | 0 |
| Navigation duration | 86.8ms |
| 已观察 Event Timing 最大 duration（不是 INP） | 48ms |
| 子资源 transferSize 合计（不含主文档） | 778,652 bytes |

没有增加生产字体、图片、动画库或前端框架请求；首次加载的最新日报 JSON 只请求一次。原始日报约 687KB，是资源主体；本轮保持数据文件不变。共享请求仅合并正在进行的读取，仍使用 no-store，不引入持久数据缓存。

本地 LCP/CLS 与目标作参考比较；Event Timing 的观察值不能等同于真实用户 INP。未运行完整 Lighthouse 评分，没有现场 CrUX/真实用户 p75 数据，因此不声称现场 Core Web Vitals 通过。

`docs/` 继续直接由原 GitHub Pages workflow 发布；没有新增 Node server 或 SSR。对基线执行范围 diff，确认 `src/`、`api/`、`config/`、`data/`、`docs/data/`、`docs/reports/`、`.github/`、`scripts/build_site_data.py` 没有改动。

## 剩余限制与取舍

- **内容质量仍受原始产物限制**：最新数据记录缺少编辑 API key，保留规则筛选结果；存在导航碎片、冗长标题和宽泛/重复分类。页面已明确阅读说明，未伪造或重写新闻。改善这些内容需要另行处理抓取和编辑链路。
- **真实 Registry 未配置**：已配置管理流程使用明确标记的本地夹具验证，不能据此宣称生产 API 连通或远程保存成功。
- **当前日期没有 PDF 文件**：保留真实 MD/TEX 下载；没有凭空生成 PDF。
- **手机标签横滑是有意取舍**：保留完整栏目文字与触摸尺寸，并提供可见提示和键盘入口；页面本身不横向滚动。
- **无真机/Safari/屏幕阅读器/现场性能数据**：当前证据来自 Windows Chrome 和内嵌浏览器；测试边界不等同所有设备保证。
